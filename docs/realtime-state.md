# 学生最新操作与智能体指导

更新：2026-11-03。

## 同步内容与时机

工作台状态保存在现有 `progress.state.workspace`，包括土壤读数、天气预报、实际降雨、连接状态、测试目的与预测、未保存规则草案，以及当前查看的观察记录、设备、阶段和测试编号。未新增数据库表或迁移版本。

- 离散操作在当前界面事件结束后发送；连续文字、滑块拖动和规则输入停顿500ms后合并，滑块释放可立即发送。
- 新旧请求顺序执行。求助、运行测试、保存规则、阶段提交及退出登录前等待最新操作和草稿保存。
- 首屏登记当前展示状态，禁止因此触发自动指导。刷新可恢复输入和规则草案，显示回到当前阶段与待测试状态，不伪装为仍在回放旧结果。
- 改变下一次测试的条件、问题或预测会清除回放定位。回放已有测试只登记真实测试编号，不产生新测试，也不改写下一次输入。
- 同步失败会显示错误，不继续以旧操作触发空闲指导；仍读取服务端阶段与开放状态。新编辑或明确求助可再次同步，不后台自动重放失败写入。

## 接口与状态含义

`POST /api/student/activity` 使用当前学生会话：

```json
{
  "stage": 2,
  "data": {
    "input": {"weather": "rainy", "sensorConnected": false, "prediction": "wait"},
    "ruleDraft": {"threshold": 2400, "minutes": 6, "skipRain": true},
    "deviceId": "sensor",
    "viewStage": 2,
    "viewedTrialId": null
  },
  "allowGuidance": false
}
```

`input`按字段合并；其他字段按此次值替换。`ruleDraft`的数字允许编辑过程中的空值或暂时越界；它不会改变实际仿真规则，正式规则保存仍进行原有校验。`allowGuidance:false`用于求助/提交前只同步；传true也必须通过后端分组与阶段检查，不能开启原本禁止的指导。

响应为 `{workspace,guidance,guidanceError}`。只在内容实际变化时保存、记录 `workspace_changed` 和更新活动时间；同值同步不延长空闲计时。旧阶段请求返回409，查看的测试编号只能属于当前学生。阶段推进清除旧工作台状态，实际测试和规则保存分别登记结果编号与清空已保存草案。

## 分组与教学限制

| 情况 | 行为 |
|---|---|
| 主动组调整条件或规则草案 | 可触发operation；沿用冷却、同阶段同类去重和每人单任务限制 |
| 响应组调整条件或规则草案 | 同步状态，不自动调用模型 |
| 查看设备、观察记录、历史测试 | 更新情境，不单独触发模型 |
| 学生主动求助 | 等待最新操作与草稿保存，仍检查是否允许求助 |
| 独立前后测、禁止首次猜想前求助 | 保留原禁答规则，不把测评答案加入模型材料 |
| 教师暂停、实验结束或已完成 | 原有写入与指导限制继续生效 |

新增operation每阶段成功一次后不再自动重复；其他test/anomaly/repeat/idle/stage触发继续遵循各自原有规则。实际干预次数可能因新增operation发生变化，研究记录中可按trigger区分。

## 读取与生成

受理时固定模型来源。实际离开队列、开始生成前读取最新草稿、工作台、最近12条相关操作、最近测试与问题明确引用的历史测试。提示词v2.6把当前设置和草案标为准备状态，只有真实测试记录提供结果。

开始生成后继续操作不会修改正在执行的模型请求，后续指导读取更新后的状态。前台普通心跳5秒，指导生成中1.5秒；实际回复时间还受模型与排队影响，不能保证固定秒数。页面并非逐帧录屏或逐键调用模型。

实现入口：`backend/src/activity.js`、`routes/student.js`、`guidance.js`、`guidance-context.js`；前端 `activity-sync.js`、`StudentPage.jsx`、`TrialWorkspace.jsx`、`LabScene.jsx`。自动化覆盖 `live-state.test.js`、`activity-sync.test.js` 及原有回归。

# 模型设置

## 使用顺序

学生下一次获取指导时，按以下顺序选择模型：

1. 学生已启用的个人模型。
2. 教师为当前实验发布的默认模型。
3. 平台默认模型（服务器 `.env` 中的配置）。

新用户默认跟随实验。未发布实验模型时沿用平台 DeepSeek API，不需要每个学生重复填写密钥。教师的个人设置仅影响自己的连接测试及其明确发布的实验，不会自动改变所有班级。

当前平台实际配置为 `https://api.deepseek.com`、`deepseek-flash`，保持原有密钥与非思考模式。2026-10-30 使用当前 API 查询到的模型为 `deepseek-flash`、`deepseek-v4-pro`；名称按接口实际返回显示。[DeepSeek 官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)将当前 `deepseek-flash` 对应为 V4.1 Flash。

## 设置个人模型

教师进入“模型设置”；学生点击页面顶部“模型设置”按钮。

- 选择个人模型，填写 API Base URL、API Key、模型 ID。
- 使用支持 OpenAI Chat Completions 格式的服务。Base URL 填到服务根路径或 `/v1`，不要填写完整的 `/chat/completions` 路径。暂不直接支持仅提供原生 Anthropic/Gemini 协议的地址。
- 思考模式默认由服务商决定；只有支持 DeepSeek `thinking` 参数的服务才选择“开启”或“关闭”。
- “测试连接”使用当前表单发出一条短请求，可能产生少量服务商费用，不会自动保存配置。
- 保存并启用后，从下一条指导开始使用。保存中的已有密钥不会回显；不修改时可留空，更换服务地址必须重新填写密钥。
- 切回默认会保留个人配置；删除个人配置会清除它并恢复默认。

不同账号的个人配置互不共享。教师和管理员页面不会显示学生填写的密钥，学生也不会得到平台或教师的密钥。

## 教师发布实验默认模型

1. 在“模型设置”中保存自己的 API 配置。
2. 在页面上方选择目标实验。
3. 将自己的配置发布为该实验默认，或选择恢复平台默认。

发布时复制当时的模型配置和密钥。之后修改、删除教师个人配置，不会改变已经发布的实验；需要再次发布才更新。实验内使用个人模型的学生保持自己的选择，其余学生从下一条指导开始使用新的实验默认模型。

调用进行中更改配置，不会改写这次调用的模型记录。指导失败会提示错误，已提交的实验操作仍保留；不会悄悄改用其他模型或平台密钥。

## 实验数据与部署

消息与事件保存实际使用的模型名称和来源，导出的指导对话 CSV 包含 `model`、`model_source`；旧消息缺少这两项时保持空值，不推测补写。四种主动/响应、线索/解释条件继续由原有教学逻辑控制。

API Key 以 AES-256-GCM 密文存入数据库，加密密钥位于数据库同目录的 `model-secrets.key`，第一次保存个人模型时创建。平台默认密钥仍在服务器 `.env` 中。接口、日志与研究导出不返回这些密钥。

`npm run backup` 会将数据库与所需的模型密钥文件配套备份。迁移服务器或恢复数据库时，需要将对应的密钥文件恢复到数据库同目录并命名为 `model-secrets.key`。已有个人模型数据但遗失该文件时，不能解密原配置，需要恢复匹配的备份；不能任意生成一份新文件代替。

用户填写的模型地址必须是公开 HTTPS 接口。后端不跟随重定向，也不向内网地址转发请求。本地自动化测试使用独立数据库和 mock 服务，不调用真实收费模型。
